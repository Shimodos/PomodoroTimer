# Стартовый промпт для Claude Code на Mac

Скопировать целиком блок ниже и вставить первым сообщением в Claude Code, запущенный из корня
репозитория. Промпт рассчитан на работу по фазам: после каждой фазы Claude Code останавливается,
показывает, что сделано и как это проверить, и ждёт команды продолжать.

---

```text
Нужно написать нативную версию этого Pomodoro-таймера для macOS. Эталон поведения — Windows-приложение
в корне репозитория (C# / WPF). Вся документация для порта лежит в docs/macos/:

- docs/macos/SPEC.md — что приложение должно делать (поведение, размеры, цвета, строки, настройки).
- docs/macos/ARCHITECTURE.md — как его строить (Swift-пакет в macos/, AppKit + SwiftUI, скрипт сборки
  .app, тесты, проверенные факты о macOS API).
- docs/macos/README.md — как я буду запускать и проверять.

Сначала прочитай оба документа полностью, потом Windows-исходники, на которые они ссылаются
(Models/AppSettings.cs, Services/TimerEngine.cs, Services/Schedule.cs, ViewModels/*.cs, Views/*.xaml,
Themes/*.xaml, Localization/Strings.en.xaml). Только после этого начинай писать код.

Правила:
1. Весь новый код — только в macos/. Windows-код, Sounds/, Assets/, Localization/*.xaml не менять.
2. Поведение берётся из Windows-кода, не придумывается. Если SPEC.md и код расходятся — прав код,
   кроме пунктов из SPEC.md §16. Если что-то непонятно — спроси, а не выбирай наугад.
3. Любой вопрос про macOS API проверяй по developer.apple.com, а не по памяти. Факты из
   ARCHITECTURE.md §5 помечены как проверенные; пункты «confirm on the Mac» проверь на этой машине
   до того, как на них опираться.
4. Файлы менять только инструментами Edit / Write, не через shell.
5. После каждого шага: `make test` и `make app` из macos/ должны проходить. Ошибку сборки чини сразу,
   не откладывай.
6. Для ручных запусков всегда `POMODORO_DATA_DIR=/tmp/pomo make run`, чтобы не трогать мои
   настоящие настройки.
7. Никаких сторонних пакетов. Swift 5.9+, macOS 13+.
8. Коммит после каждой фазы с понятным сообщением; build/ и .build/ в .gitignore.

Фазы (после каждой остановись, расскажи, что сделано, что и как проверить вручную, и жди «дальше»):

Фаза 1 — каркас и логика.
  macos/Package.swift, Makefile, Info.plist, scripts/bundle.sh, scripts/icon.sh, scripts/strings.py,
  Localization/overrides.{en,uk,ru}.json. PomodoroCore целиком: AppSettings (Codable, те же ключи
  JSON), SettingsStore, TimerEngine, Schedule, Localizer, цвета, ActivityLog/CrashLog, SessionText.
  Тесты из ARCHITECTURE.md §6 — все зелёные. PomodoroApp пока только открывает пустое окно 340×540 и
  ставит иконку в строку меню; `make run` открывает .app с иконкой и именем Pomodoro.

Фаза 2 — главное окно.
  MainViewModel, MainView: заголовок с точкой и кнопками, вкладки, кольцо, время, статус, ссылка
  «Focus running · mm:ss», Edit (редактор длительности), кнопки Reset / Start / Skip, точки циклов,
  степпер сессий, подпись сессии, компактный режим, pin. Всё по SPEC.md §6–7.

Фаза 3 — окно настроек.
  Четыре страницы, черновик настроек, живой предпросмотр темы / цветов / языка с откатом по Cancel,
  Save применяет всё как в SPEC.md §8. Звуки: список встроенных, свои файлы через open panel,
  предпросмотр, громкость.

Фаза 4 — системная интеграция.
  Иконка в строке меню с минутами и меню (Show / Start–Pause / Quit), уведомления UserNotifications,
  всплытие окна при конце фазы, always on top, «закрыть / свернуть в строку меню», объект входа через
  SMAppService, сохранение позиции окна, Dock reopen, главное меню с ⌘, ⌘W ⌘M ⌘Q и пробелом.

Фаза 5 — финал.
  Тема System следует за системой вживую, все три языка проверены на обоих окнах, логи как в SPEC.md
  §3–4, `make zip`, раздел про macOS в README.md репозитория (как собрать, где файлы, что
  Gatekeeper скажет про неподписанную сборку). Пройди ручной чек-лист из ARCHITECTURE.md §6 и
  перечисли, что из него не смог проверить сам.

Начни с фазы 1.
```

## Подсказки на случай проблем

- **`swift build` не находит SDK или SwiftUI** — установлен только Command Line Tools. Поставить
  Xcode из App Store и выполнить `sudo xcode-select -s /Applications/Xcode.app`.
- **Приложение падает на старте с `bundleProxyForCurrentProcess is nil`** — запущено не как `.app`
  (через `swift run`). Запускать `make run`.
- **Уведомлений нет** — macOS спрашивает разрешение один раз; проверить Системные настройки →
  Уведомления → Pomodoro. После пересборки с ad-hoc подписью разрешение может сброситься.
- **«Открывать при входе» не появляется** — в Системных настройках → Основные → Объекты входа
  элемент может ждать подтверждения; приложение показывает подсказку под переключателем.
- **Что-то ведёт себя не так, как на Windows** — спросить Claude Code: «сравни с Windows-кодом в
  <файл>». Эталон всегда там.
